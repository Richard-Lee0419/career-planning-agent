# B 方案执行计划

目标：为中国大陆学生提供可信的职业能力差距演示，在现有 IT 功能上试点两个非 IT 就业领域、合计约 6 个角色。职业标准扩展与真实招聘样本扩展分别说明。

## 执行顺序

| 阶段 | 交付内容 | 进入下一阶段的条件 | 状态 |
| --- | --- | --- | --- |
| 1. 可靠性基线 | 技能匹配、会话关联持久化、关键 AI 输出校验；回归测试；CI 配置 | 已确认失败场景得到保护，现有检查通过 | 已通过：后端40项、前端4项；CI尚未在GitHub执行 |
| 2. 来源与职业标准 | 两个领域的审核试点标准、技能别名、来源/地区/版本；幂等导入 | 每个标准有可查看的来源与范围说明，导入不覆盖已有数据 | 已通过：6角色、2领域；联合后端52项 |
| 3. 跨领域使用流程 | 动态问卷、领域内比较、来源展示、目标职业提示；无标准时明确限制 | 两类非 IT 画像能完成主流程，信息不足不会得到虚假分数 | 已通过：后端60项、前端8项；lint及生产构建通过 |
| 4. 可复现交付 | 完整检查、真实后端/AI 验证、浏览器验证、演示材料、运行说明与设计取舍 | 明确记录通过、失败、未验证事项；核心闭环能重现 | 已交付：后端64项、前端8项、lint/构建；两领域真实API闭环；浏览器恢复/进度/导出通过，生成失败及建议质量局限保留 |

数据来源核实可与阶段 1 并行准备，但阶段 2 的导入及阶段 3 的功能改动在前阶段检查通过后实施。

## 范围与成本

原估计：基线 3–5 有效工作日；完整小试点合计 5–9 日，每日约 6 小时。这是估计，不是工期保证。本轮按约 40 有效小时控制；若基线修补或来源整理超出预算，扩展缩为一个领域 3 个角色，必要时保留可信 IT 演示。

本轮沿用 React、FastAPI、SQLite；不增加招聘爬虫、全职业自动评分、全专业自动映射、薪资热度统计或模型训练。未经审核的职业不进入确定性评分。第三方代码与数据的来源和适用条款分别核对。

## 证据边界

- 自动化测试替换外部 AI，验证计算、HTTP、数据库、异常处理和保存恢复；不能证明真实模型质量。
- 真实 AI 验证使用合成画像和隔离数据库，并记录模型、时间和结果；不能推导推荐准确率或用户收益。
- 浏览器演示使用真实后端，不以拦截所有 API 的截图作为核心流程通过证据。
- 本地工作区改动不等于 GitHub 已更新。没有用户明确指令时不提交、推送或部署。

阶段完成情况及实际命令将在 `docs/validation.md` 记录。

## 本轮交付后的边界

2026-10-12首次完成上述四阶段，当时未提交或推送。职业标准已经扩展，招聘语料没有扩展；当时的真实模型失败、重复已有能力和顾问跳过待办原文保留。后续改进以这些具体失败为依据。

若继续投入，优先做少量合成画像的人工建议评审、招聘/培训任务来源补核和从零安装验证；模型质量改进应以遗漏差距、跳过未完成任务等具体失败为依据。本轮不追加复杂架构或自动多行业采集。

## 用户要求继续完成并发布后的执行

| 后续阶段 | 任务及验收 | 结果 |
| --- | --- | --- |
| 1. 建议与进度修正 | 任务目标对应差距，最多一次修正，压缩后保留所选路径下一待办 | 回归通过；六角色分两批真实闭环；六条顾问建议均指向待办。内容适用性局限保留。 |
| 2. 来源与可复现交付 | 培训任务补核；六画像内容阅读；干净环境安装、检查；实际UI演示 | v2来源包；67后端/8前端通过；助手内容评审；Edge真实生成/进度/下载；发现的依赖漏洞修复后npm审计为0。人事直接雇主来源未获充分正文证据。 |
| 3. GitHub发布 | 文件/密钥/链接检查，提交并推送main，核对远程Actions | 已获得用户明确授权；具体提交及Actions以GitHub仓库为准，本地记录见validation。 |

不把工程修复等同于所有建议可靠。岗位从业者独立评审、真实练习完成反馈、企业原始数据的公开许可和更多行业招聘语料，仍是范围之外或需要外部证据的工作。
