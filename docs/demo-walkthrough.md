# 本次v2演示与可选浏览器检查

当前证据见[发布验收](validation.md)与[索引](demo/README.md)。六角色可用`scripts/verify_live_pilot.py --all-roles --roles 岗位名`选择小批量合成样例；真实AI运行会产生模型调用。默认仍只验证内容运营和招聘助理。同IP一小时注册最多五次，不能直接把六账号一次快速注册的429认作建议生成失败。

可选真实UI检查使用`frontend`开发依赖中的Playwright。先通过界面准备一次性`pilot_live_`开头的合成账号：内容运营目标、文案撰写/图文排版、团队合作、每周6–10小时；生成一个两任务版本并只勾第一项。把自己的临时用户名、密码及路径ID填写到仓库已忽略的`tmp/browser-account.json`中，字段为`username`、`password`、`roadmap_id`。不要提交该文件。

```powershell
# 有Microsoft Edge时用独立无头会话；不使用个人浏览器资料
node scripts/verify_browser_smoke.cjs --base-url http://localhost:5173 --channel msedge --output-dir tmp/browser-smoke
# 可选：再通过页面调用真实模型生成新版本，不自动重试
node scripts/verify_browser_smoke.cjs --base-url http://localhost:5173 --channel msedge --generate-new --output-dir tmp/browser-smoke
```

没有Edge时，在`frontend`中执行`npx playwright install chromium`后省略`--channel`。脚本没有拦截API；失败退出非零，结果、截图和浏览器真实下载均写到指定目录；凭据不写进结果。它验证一个明确合成场景，不能代替所有页面与移动端测试。旧v1演示步骤如下，标准版本和输出不应与v2结果混用。

# 非 IT 试点核心流程演示

目标：在中国大陆学生场景中，演示“自述能力 → 岗位标准覆盖 → 小规模行动计划 → 保存进度 → 顾问 → 版本导出”。六个试点角色不代表完整职业目录；本轮没有新增招聘语料。

## 启动

按[README](../README.md)安装依赖并配置自己的 AI Key 与 JWT 密钥。使用独立数据库，以下命令在仓库根目录执行：

```powershell
$env:CAREER_DATABASE_PATH = "data/portfolio-demo.db"
$env:AI_REQUEST_TIMEOUT_SECONDS = "60"
python scripts/seed_pilot_standards.py
python scripts/seed_demo_data.py
uvicorn main:app --host 127.0.0.1 --port 8011
```

另开终端：

```powershell
cd frontend
$env:VITE_API_PROXY_TARGET = "http://127.0.0.1:8011"
npm run dev -- --port 5174 --strictPort
```

打开 `http://127.0.0.1:5174`，新建演示账号。60 秒是本轮隔离演示使用的单次模型超时配置；默认示例配置为30秒。服务仍可能超时，失败后不会将无效路径保存为正常结果。历史查看不再次调用模型。

## 两条合成画像

这些是演示输入，没有真实学生、求职或使用效果含义。姓名可自行填写，学历本科、大三，每周学习时间6–10小时。

| 项目 | 市场与内容 | 人力资源 |
| --- | --- | --- |
| 专业 | 市场营销 | 人力资源管理 |
| 探索领域 | 市场与内容 | 人力资源 |
| 兴趣 | 内容传播 | 招聘与培训 |
| 当前能力 | 文案撰写、图文排版 | Excel、简历初筛、面试安排 |
| 软素质 | 团队合作 | 团队合作 |
| 目标 | 内容运营 | 招聘助理 |
| 合成经历 | 课程练习中写宣传稿并排版，团队完成一份练习稿 | 用虚构简历练习初筛，整理候选人表和模拟面试排期 |
| 当前规则参考 | 37% | 50% |

规则含80%核心技能、15%软素质和5%目标/兴趣。百分比说明这份自述对这份标准的加权覆盖，不是职业适合度或录用概率。换用“沟通协调、细致负责、保密意识”等软素质，参考值会改变；只有实际掌握且有经历支持的能力才应填写。

## 操作与核对

1. 完成四步测评。在第二步切换领域，确认核心能力及软素质选项相应变化；在第三步仍应只看到该领域岗位，同时能自行输入目标。
2. 生成画像后进入职业探索页。确认当前目标保留、卡片只属于所选领域；展开“查看工作任务、依据与适用范围”，核对来源类型、版本、任务、链接和限制。切换另一个领域，只应更换探索卡片，不应改写自己的主目标。
3. 为目标生成路径。非 IT 试点任务应包含动作、产出、自查方法和耗时；计划最多4周，任务估计受所填时间预算约束。资源只能引用试点已核对链接，建议内容仍需判断和复核。
4. 勾选一项完成，刷新页面或重新打开历史版本，确认同一任务和进度恢复，标准来源仍为生成时快照。
5. 进入关联该路径的 AI 顾问，询问“根据我完成的任务，本周下一步做什么”。重新打开对话，确认目标、路径关联及回答保存。
6. 点击“保存本次规划结果”，检查 Markdown 中的版本号、专业、目标、标准版本、任务及勾选状态与页面一致。

无能力信息应显示“信息不足”，不生成百分比；自填未知目标应保留并说明暂无标准。未分类或被修改的标准不获得确定性评分；没有来源的早期路径也不能补套当前来源。目录不可用时页面显示明确失败状态，仍可在测评自行填写能力和目标。

## 自动复现真实 API

在隔离服务已启动后，可选择运行以下验收。它注册两个新合成账号并消费真实模型请求；账号密码和访问令牌不写入证据文件，客户端不自动重试 AI 端点。

```powershell
python scripts/verify_live_pilot.py --base-url http://127.0.0.1:8011 --http-timeout 200 --backend-ai-timeout 60 --output-dir tmp/my-live-check
```

结果包含输入、HTTP状态、断言、保存的计划及顾问输出。它能验证接口和持久化，并不能评价职业建议正确率。本轮真实运行、人工读阅及浏览器结果见[验证记录](validation.md)；[证据索引](demo/README.md)链接最终API记录、两领域报告、浏览器结果、截图与历史失败。发生过的失败记录保留，不能将一次成功当作可用性统计。

最终两领域API闭环通过；浏览器还验证了真实生成历史的进度恢复与导出，但另一次浏览器生成因超过阶段上限被拒绝。演示新生成可能失败，应展示实际错误；若回看已生成版本，要明确它是历史结果。当前建议仍可能重复已有能力或跳过待办，不能把“生成成功”解释为职业建议正确。
